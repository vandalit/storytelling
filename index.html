App mobile-first para construcción narrativa por cards. Personajes, escenas, beats, worldbuilding — todo conectado vía tags. Sin metodología impuesta.

◆ Abrir prototipo interactivo Ver repositorio ↗
⚡
Captura mínima
Una idea en 2 taps. El tipo y el proyecto son opcionales — la card llega al Inbox y se clasifica después.
◉
Cards on-demand
Los campos se despliegan según el tipo. Personaje activa Psicología y Arco. Escena activa Dramaturgia y Beat. Sin secciones vacías.
#
PKM bidireccional
Los tags conectan cards automáticamente. Si Ana Ruiz aparece en tres escenas, la card de Ana lo muestra sin configuración manual.
◈
Timeline libre
Posiciona escenas en el arco (0–100%) con etiquetas libres. Sin metodología fija: Snowflake, STC, Hero's Journey o la tuya.
◆
Multi-proyecto
One-shot, serie, videojuego, D&D. Cada proyecto tiene su tipo y división (actos, episodios, niveles). Franquicias cross-project en roadmap.
▶
3 vistas
Mazo staggered para overview, Flipbox para revisar card a card, Timeline para ver el arco narrativo completo.

Stack Android MVP

El prototipo valida la UX antes de comprometer la arquitectura. La decisión Room vs Firestore se toma post-POC según lo que revelen los flujos.

Kotlin Jetpack Compose Navigation Compose Room (SQLite) LazyVerticalStaggeredGrid Firebase / Firestore Repository Pattern post-MVP: sync + export
Room (local-first) — MVP offline, FTS5 para búsqueda, cero latencia.
Firestore (sync) — multi-dispositivo, colaboración, tiempo real.
Decisión: Repository pattern abstrae la fuente — el switch es transparente.
Modelo de datos (Card)

Unidad atómica de la app. Un solo tipo con campos extendidos on-demand por tipo de card.

// Card — unidad atómica Card { id : UUID titulo : String? // null = sin título (inbox) cuerpo : String // único campo requerido tipo : CardType // blanca | personaje | escena | … proyecto_id : UUID? // null = Inbox contenedor_id : UUID? // acto | episodio | nivel tags : String[] // #juan, #acto-2 → relaciones auto estado : 'activa' | 'borrador' | 'archivada' fecha_creacion : DateTime fecha_edicion : DateTime // on-demand según tipo: personaje : PersonajeData? // psicología, arco, físico escena : EscenaData? // dramaturgia, beat_posicion 0.0–1.0 }
